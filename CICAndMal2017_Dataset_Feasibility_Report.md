## 1. Executive Summary

This report delivers an empirical forensic audit of the downloaded **CICAndMal2017** dataset to determine its technical feasibility for building a **live, real-time network-based intrusion detection system (NIDS)** that monitors packet flows from a physical Android smartphone.

### Key Forensic Findings
1. **Physical Dataset Makeup**: The examined local directory contains **2,126 CSV files** totaling **1.22 GB (1,311,278,522 bytes)**, comprising **2,616,579 network flow records**. 
2. **Absence of Raw PCAP Files & APKs**: **Zero `.pcap` or `.pcapng` packet capture files** and **zero Android APK binaries** reside in the local directory. The files present are solely pre-extracted flow feature CSVs generated by **CICFlowMeter** (historically named *ISCXFlowMeter*), as proven by the filename suffix `.pcap_ISCX.csv`.
3. **Class Scope & Nature**: The dataset contains **1,210,210 benign flows (46.25%)** and **1,406,369 malware-associated flows (53.75%)** across 4 major Android malware categories (**Adware, Ransomware, Scareware, SMSmalware**) spanning 42 distinct malware families.
4. **Feasibility Verdict for Live Phone NIDS**:
   - **For Mobile Malware C2/Adware/Exfiltration Detection**: **Partially supported**. The dataset provides rich bidirectional flow-level timing and length statistics for mobile malware communication. However, it cannot be deployed directly to a live modern phone without addressing severe **temporal drift** (2015–2017 TLS/HTTP patterns vs. modern TLS 1.3 / DoH / QUIC) and **feature extractor calibration**.
   - **For General Network Intrusion Detection (DDoS, Port Scanning, Exploit Ingestion, Brute-Force)**: **NOT SUPPORTED**. The dataset contains **zero network-infrastructure attacks**. It is an endpoint application malware communication dataset, not an infrastructure attack dataset. Hybridization with network intrusion datasets (such as **CIC-IDS2017** or **CSE-CIC-IDS2018**) is mandatory if general intrusion detection is required.

## 3. Raw PCAP Analysis

### 3.1 Local Availability Status
**Finding:** **Raw `.pcap` and `.pcapng` files are ABSENT from the local dataset directory.**  
The local directory holds exclusively the CSV outputs of feature extraction. Therefore, low-level packet byte inspection, deep packet inspection (DPI), payload reassembly, and raw hex forensics cannot be directly performed on this machine without acquiring the upstream raw PCAP archives from the UNB repository.

### 3.2 Inferences from Filename Structure & Extracted Metadata
Despite the lack of local PCAP binaries, rigorous forensic inferences can be derived from the CSV naming conventions and metadata columns:

1. **Naming Schema**: Files follow the strict naming grammar:
   `[MM_DD_YYYY]-[CategoryCode]-[FamilyName]-[DetectionVendor]-[SampleHash].pcap_ISCX.csv`  
   - *Example*: `06_14_2017-ad-dowgin-gdata-1c4e357a8ec5f13de4ffd57cc2711afe.pcap_ISCX.csv`
   - *Date of Capture*: June 14, 2017
   - *Category Code*: `ad` (Adware), `be` (Benign), `ra` (Ransomware), `sc` (Scareware), `sms` / `ps` (SMSmalware / Premium SMS)
   - *Malware Family*: `dowgin`
   - *Detection Engine*: `gdata`, `kaspersky`, `fortinet`, `eset`, `sophos`, etc.
   - *Sample Hash*: MD5 / SHA-256 fingerprint of the executed APK.
   - *Origin Artifact*: The file was generated directly by running `ISCXFlowMeter` against a capture file named `06_14_2017-ad-dowgin-gdata-1c4e357a8ec5f13de4ffd57cc2711afe.pcap`.

2. **Network Topography and Testbed IP Leakage**:
   - Flows originating from the Android devices reveal client private IP addresses in the subnet `10.42.0.0/24` (frequent IPs: `10.42.0.211`, `10.42.0.42`, `10.42.0.151`).
   - Remote destination endpoints include public CDN IPs, Facebook CDN (`31.13.71.x`, `157.240.18.x`), Google infrastructure (`172.217.x.x`), Microsoft (`13.107.x.x`), and arbitrary third-party advertising / C2 endpoints.
   - Protocols present in the flow logs are predominantly **TCP (IP protocol 6)** and **UDP (IP protocol 17)**.

3. **Encryption & Payload Observability in a Live Pipeline**:
   - Modern Android traffic is heavily encrypted (>95% TLS 1.3 / HTTPS / QUIC).
   - In accordance with cybersecurity principles, **payload contents (passwords, tokens, encrypted message bodies) are unobservable** on the wire without installing custom CA certificates or utilizing dynamic instrumentation (e.g., Frida) on the device.
   - However, **all 84 CICFlowMeter features are derived strictly from Layer 3 and Layer 4 packet headers and inter-packet arrival times**. These features (packet sizes, flow duration, inter-arrival time distributions, TCP flags, byte throughput) remain **100% observable even under end-to-end encryption**.

### 4.2 Known Structural Anomalies in the Schema
1. **Duplicate Column Name**: Column `[40]` and Column `[61]` are both titled `'Fwd Header Length'`. This is a documented flaw in CICFlowMeter v1/v2 Java source code. When parsing with standard pandas or SQL engines, duplicate column names will collide and must be disambiguated (e.g., `Fwd Header Length.1`).
2. **Bulk Rate Zero-Variance Columns**: Columns `Fwd Avg Bytes/Bulk`, `Fwd Avg Packets/Bulk`, `Fwd Avg Bulk Rate`, `Bwd Avg Bytes/Bulk`, `Bwd Avg Packets/Bulk`, and `Bwd Avg Bulk Rate` consist entirely of zeros across the mobile dataset because bulk transmission thresholds were not triggered in short-lived smartphone interactive flows.
3. **Flow Duration Units**: The `Flow Duration` metric is recorded in **microseconds** ($\mu s$). Calculating rates requires dividing by $10^6$.

### 4.5 Key Observations on Labels
1. **Benign Traffic Inside Malware Directories**:
   - In `Scareware-CSVs`, exactly **4,276 flows** are labeled `BENIGN`.
   - In `SMSmalware-CSVs`, exactly **419 flows** are labeled `BENIGN`.
   - *Forensic Explanation*: When malware runs on an Android device, system background services (Google Play services, NTP, DNS, Android OS sync) execute alongside the malicious process. CICFlowMeter preserved those background benign flows within the capture.
2. **Ambiguous Class Labels**:
   - `MALWARE` appears 2,828 times in `Scareware-CSVs`.
   - `SCAREWARE` appears 7,430 times inside `SMSmalware-CSVs`.
   - 5 rows have an empty label (`''`).
   - *Sanitization Directive*: In model preparation, these records must either be remapped to their coarse category or pruned during dataset cleansing.

## 5. Dataset Quality, Biases, and Critical Limitations

### 5.1 Data Cleaning & Numeric Hygiene
- **Missing / NaN Values**: In audited samples, fewer than 0.01% of rows contain empty or unparseable fields (primarily caused by occasional truncated lines at file ends).
- **Infinite Values**: `Flow Bytes/s` and `Flow Packets/s` produce `Infinity` in raw CICFlowMeter when `Flow Duration == 0`. In the cleaned files, instances of `Flow Duration == 0` are minimal (approx. 0.006%), but any live implementation must explicitly replace division-by-zero results with 0 or a max-value sentinel.
- **Negative Durations**: No negative durations were observed in the audited sample, confirming that timestamp subtraction issues present in earlier CIC tools were addressed in this version.

### 5.2 Critical Experimental Biases & Leakage Risks

#### 1. Severe Network Identifier Leakage
The columns `Flow ID`, `Source IP`, `Destination IP`, `Source Port`, and `Timestamp` present an extreme risk of **data leakage**:
- In the testbed, phones were assigned static/predictable IP addresses (`10.42.0.211`, `10.42.0.42`, `10.42.0.151`).
- Specific destination IPs and ports belong to known C2 servers or Google test servers.
- **If these columns are included as features, any machine learning model will achieve an artificial >99.9% accuracy by simply memorizing IP addresses rather than learning behavioral traffic patterns.**
- **MANDATORY RULE:** `Flow ID`, `Source IP`, `Destination IP`, `Source Port`, and `Timestamp` MUST BE STRIPPED prior to feature matrix generation.

#### 2. Temporal Decay & Protocol Drift (2017 vs. Present)
- The dataset was recorded in **2017** on Android 5.0 and 6.0.
- Modern Android devices (Android 12–15) differ radically:
  - **TLS 1.3** is universally enforced; TLS 1.0/1.1 are deprecated.
  - **DNS over HTTPS (DoH)** and Private DNS (DoT) are default in modern Android, eliminating plaintext UDP port 53 DNS flow fingerprints.
  - **QUIC / HTTP/3 (UDP port 443)** dominates Google, YouTube, Instagram, and web traffic today, whereas 2017 traffic was almost entirely TCP.
  - Background execution limits (Doze mode, App Standby buckets) restrict background app beaconing significantly compared to Android 6.0.

#### 3. Flow Split & Subflow Aggregation Mismatch
- CICFlowMeter defines a flow timeout of **120 seconds** (idle timeout typically 5 seconds).
- In a live detection system, waiting 120 seconds for a flow to terminate before classifying it introduces a **2-minute detection delay**, which is unacceptable for real-time intrusion prevention.

### Recommended Dataset Strategy: Two-Headed Classifier
1. **Network Attack Detector (Head A)**: Train on **CIC-IDS2017** / **CSE-CIC-IDS2018** (features: DoS/DDoS, Port Scanning, Brute Force).
2. **Mobile Malware Communicator Detector (Head B)**: Train on **CICAndMal2017** (features: Adware C2, Ransomware lockscreen exfiltration, SMS premium fraud beaconing).
3. **Harmonized Schema**: Both datasets share the exact **CICFlowMeter 84-feature specification**, allowing a single real-time feature extraction pipeline to serve both models simultaneously!

## 8. Proposed System Architecture for Live Packet Pipeline

To capture traffic from a physical Android phone and detect malicious patterns in real time, the following architecture is designed:

```
[ Android Smartphone ] (Unmodified, Real User Traffic)
          │
          │ Wi-Fi 802.11 (WPA2/WPA3 Private Association)
          ▼
┌───────────────────────────────────────────────────────────┐
│ Laptop Wi-Fi Hotspot Gateway (Authorized Tap)            │
│  - Windows Mobile Hotspot / Linux Hostapd                 │
│  - Virtual Adapter: e.g., "Local Area Connection* 10"     │
│  - NAT Router: 192.168.137.1 (Leases DHCP to Phone)       │
└─────────────────────────┬─────────────────────────────────┘
                          │
                          │ Promiscuous / Raw Packet Capture (WinPcap / Npcap / Scapy)
                          ▼
┌───────────────────────────────────────────────────────────┐
│ Packet Sniffing & Flow Assembler Engine                   │
│  - Engine: NFStream / Scapy / Python-CICFlowMeter         │
│  - Sliding Window Flow Timeout: 5s inactive / 15s max dur │
│  - Aggregates bidirectional packet sizes, IATs, TCP flags │
└─────────────────────────┬─────────────────────────────────┘
                          │
                          │ Raw 84-Feature Vectors
                          ▼
┌───────────────────────────────────────────────────────────┐
│ Feature Preprocessing & Alignment Engine                  │
│  - Strip Identifiers: Drop Flow ID, IP Addrs, Ports, Time  │
```

### 8.1 Technical Details on Live Packet Capture

#### Why Ordinary Wi-Fi Promiscuous Mode Fails
An ordinary laptop Wi-Fi adapter placed into "promiscuous mode" connected to a standard home router **CANNOT** capture unicast traffic sent between the Android phone and the router.
- In modern WPA2-PSK and WPA3 networks, each wireless client negotiates a unique **Pairwise Transient Key (PTK)** during the 4-way handshake.
- The laptop's Wi-Fi card only decrypts packets encrypted with its own PTK or broadcast packets encrypted with the Group Temporal Key (GTK). All unicast data frames between the phone and router appear as unreadable 802.11 encrypted payload noise.

#### The Practical Solution: Laptop as Gateway (Wi-Fi Hotspot)
1. Enable the **Mobile Hotspot** feature on the analyst laptop (Windows Hosted Network / Virtual Wi-Fi Adapter).
2. Connect the Android phone directly to this laptop-hosted SSID.
3. The laptop acts as the Layer 3 Default Gateway (NAT router) for the phone.
4. **All IP traffic from the phone must pass through the laptop's virtual network interface (`\Device\NPF_{...}` via Npcap).**
5. Capturing on this virtual interface captures 100% of the phone's decrypted Layer 3/Layer 4 IP packets cleanly without rooting the phone or installing intrusive software.

### 8.2 Live Feature Extractor Alignment
To eliminate **Training-Serving Skew**:
- Do not compute features using arbitrary custom math. Use a verified Python implementation such as `nfstream` configured to output CICFlowMeter metrics or the `cicflowmeter` Python package.
- **Microsecond Timestamps**: Ensure packet arrival intervals are measured with high-resolution clocks (`time.perf_counter()` or libpcap hardware timestamps).
- **Subflow Timeout**: Use a sliding subflow expiration (e.g. 15-second subflow flush) so the system does not wait 2 minutes for idle mobile connections to expire before triggering an alert.

## 8. Machine Learning Evaluation & Experimentation Plan

### 9.1 Data Cleansing & Label Standardization
1. **Remove Ambiguous Rows**: Drop rows with blank labels (5 rows) and rows with the ambiguous `MALWARE` label (2,828 rows) or re-categorize them.
2. **Handle Duplicate Header Bug**: Rename the duplicate column 61 from `Fwd Header Length` to `Fwd Header Length.1`.
3. **Drop Leaky Columns**: Remove `Flow ID`, `Source IP`, `Source Port`, `Destination IP`, `Destination Port`, and `Timestamp`.
4. **Clean Infinite / NaN Values**: Replace `Infinity` and `-Infinity` in `Flow Bytes/s` and `Flow Packets/s` with the 99.9th percentile value or `0`, and impute rare `NaN` with column medians.
5. **Drop Zero-Variance Columns**: Drop constant zero columns (`Fwd Avg Bytes/Bulk`, `Fwd Avg Packets/Bulk`, `Fwd Avg Bulk Rate`, `Bwd Avg Bytes/Bulk`, `Bwd Avg Packets/Bulk`, `Bwd Avg Bulk Rate`).

### 9.2 Defensible Split Strategy (Leakage-Proof)
- **Do NOT use standard random row-level k-fold cross-validation!**
- If flows from the same APK execution (or malware family) appear in both train and test folds, the model will memorize flow sequence artifacts from that specific app session, producing artificially inflated metrics.
- **Strategy: Grouped-by-Sample / Grouped-by-Family Split**:
  - Partition the data such that all flows from a specific APK sample hash (or specific malware family) exist **strictly in the training set or strictly in the test set**.
  - Evaluate on "Zero-Day" test families to measure genuine generalization capability to unseen mobile malware.

### 9.3 Recommended Baseline Models
1. **LightGBM / XGBoost**: Optimal for tabular flow metrics; handles non-linear interactions, fast inference latency (<0.5 ms per flow).
2. **Random Forest Classifier**: Serves as a solid, interpretable bagging baseline.
3. **Isolation Forest / One-Class SVM**: Used in parallel as an unsupervised novelty detector to flag unexpected zero-day patterns in live traffic.

### 9.4 Comprehensive Evaluation Metrics
Report the following metrics on held-out test splits:
- **Per-Class Precision, Recall, and Macro F1-Score**: Essential due to class imbalances across families.
- **False Positive Rate (FPR)**: In intrusion detection, an FPR exceeding 1% creates alert fatigue that renders a system unusable in production. Target FPR: **< 0.1%** on benign traffic.
- **Inference Latency & Throughput**: Measure mean and 99th-percentile inference time per flow on CPU. Target: **< 2 ms per flow** to support gigabit streaming rates.

## Concise Final Recommendation

### **“Can we use this dataset to build a live Android-phone network intrusion detection system, and what additional data or components are required?”**

**Final Answer:**  
**Partially — with critical caveats and mandatory supplemental components.**

1. **What CICAndMal2017 CAN Do**:
   - It **can** be used to detect **Android malware-associated communication** (specifically Adware beaconing, Ransomware communication, Scareware fake-alert downloads, and SMS fraud traffic) from an Android phone, using Layer 3/4 flow statistics without decrypting TLS payloads.

2. **What CICAndMal2017 CANNOT Do Alone**:
   - It **cannot** detect general network-infrastructure attacks (DoS/DDoS, Nmap port scanning, SSH/FTP brute force, web vulnerability exploitation). It contains **zero** instances of these attacks.
   - It **cannot** be deployed directly onto a live phone without compensating for **temporal drift** (2017 Android 6.0 traffic patterns vs. modern Android 14/15 TLS 1.3 / DoH / QUIC behavior).

3. **Mandatory Additional Components Required**:
   - **Supplemental Network Intrusion Dataset**: Ingest **CIC-IDS2017** or **CSE-CIC-IDS2018** to train a complementary detector for DoS, port scans, and brute-force attempts. Both share the exact same 84-feature CICFlowMeter schema.
   - **Live Capture Architecture**: Set up a **Laptop Wi-Fi Hotspot** (NAT gateway) so all phone packets route through the laptop's capture adapter. Ordinary Wi-Fi promiscuous sniffing cannot decrypt WPA2/WPA3 unicast traffic.
   - **Live Flow Aggregator**: Implement a streaming flow engine (`nfstream` or `cicflowmeter`) with a 5–15 second active timeout to extract the identical 84 features in real time without identifier leakage.
   - **Modern Benign Baseline Data**: Collect 1–2 hours of modern benign traffic from your current phone to fine-tune the classifier and prevent false positives caused by 2017-era protocol obsolescence.
